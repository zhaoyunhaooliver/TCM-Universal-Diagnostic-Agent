# 🌿 中医药知识图谱与智能辨证系统研发规划书

---

## 📌 项目定位与目标
基于国家中医药诊疗标准（GB/T 16751）、国家医保代码体系（A/B/C系列）及经典名方与实战医案，构建高严谨度、低幻觉、可解释的 **“理、法、方、药、证、症、案、籍”八位一体中医药知识图谱**，并在此基础上开发具备**智能辨证推理、名方推荐、随症加减化裁与配伍禁忌审查**的现代辅助诊疗系统。

---

## 阶段一：前期工作 · 数据治理与全链条网络闭环（先做什么）
> **核心任务**：打破数据孤岛，消除图谱中的“断头路”，把各个独立的模块真正缝合成一个能够正向反向推理的闭环网络。

### 1.1 跨模块主干关系构建（核心骨架连接）
- [ ] **证候 ──[推荐治法]──> 治法**：
  - 基于汉语病机词法对称规则引擎（如“风热”$\leftrightarrow$“辛凉解表”，“脾虚”$\leftrightarrow$“健脾益气”），自动化生成高置信度【证-法】关系。
- [ ] **疾病 ──[常见分型]──> 证候**：
  - 依据国家权威《中医常见病诊疗指南》与教材规范，补充常见病名下的 3~6 个经典分型连线（如感冒病 $\to$ 风寒/风热/暑湿/气虚感冒证）。
- [ ] **方剂 ──[主治主证]──> 证候**：
  - 依据方剂说明与主治字段，将 593 首方剂与 2050 个国标证候精准对接。

### 1.2 症状文本的深度细化提取
- [ ] **从 2050 个证候定义中自动化拆解症状**：
  - 编写 NLP 槽位抽取脚本，提取“临床以……为特征”中的【核心主症】。
  - 提取“舌质……舌苔……”与“脉……”生成专有【舌脉关系】。
  - 提取“伴见……等为特征”生成【次要兼症】。
  - 标注关系权重属性（主症权重 0.6，舌脉 0.3，兼症 0.1）。

### 1.3 临床安全性审查网络建立
- [ ] **中药配伍禁忌入库**：
  - 录入“十八反”（如甘草反甘遂、乌头反半夏）与“十九畏”实体关系（`INCOMPATIBLE_WITH`）。
- [ ] **妊娠用药禁忌库**：
  - 标定慎用与禁用中药。

## 阶段二：中期工作 · 智能辨证推理算法与后端引擎开发（中间做什么）
> **核心任务**：图谱不能只是一张好看的静态图，必须写出核心推理算法，让它能“像老中医一样思考”。

### 2.1 智能辨证打分算法（Symptom $\to$ Syndrome）
- [ ] **加权匹配评分引擎**：
  - 输入：患者多维症状集合（包含主诉、次症、舌象、脉象）。
  - 算法：计算候选证候图节点的加权覆盖率（主症 + 舌脉一票否决/强权），输出 Top 3 推荐证候及置信度百分比。
- [ ] **主证与兼夹证判定逻辑**：
  - 最高分作为“主证”，剩余高重合度症状群归为“兼证”（如主证：表寒肺热证，兼证：脾胃虚弱）。

### 2.2 处方推荐与随症加减引擎（Syndrome $\to$ Formula & Herb）
- [ ] **主方召回**：
  - 顺着主证节点直接检索首选经典名方。
- [ ] **随症加减机制（对症下药）**：
  - 对未能被主方解释的剩余孤立症状（如兼咽痛剧烈、兼便秘），顺着图谱规则推荐加用特异性单味药（如加射干、加大黄）。
- [ ] **配伍安全性实时拦截**：
  - 推荐处方与加减药物生成后，遍历药-药禁忌子图，自动告警“十八反/十九畏”冲突。

### 2.3 真实医案验证引擎（Case-Based Reasoning, CBR）
- [ ] 检索 1,737 例实战医案库中舌脉、主诉最相似的历史案例，作为推理结果的“实战证据背书”。

### 2.4 后端接口封装（API 服务层）
- [ ] 使用 Python (FastAPI) 编写服务端接口：
  - `/api/symptoms/search`：症状智能联想检索。
  - `/api/diagnose`：辨证论治核心接口（入参：症状列表；出参：主证、兼证、治法、方剂、加减用药、安全审计报告、相似医案）。

## 阶段三：后期工作 · 交互系统呈现与大模型 GraphRAG 融合（最后做什么）
> **核心任务**：打包落地，让产品可以直接使用、展示或面向真实患者/医生交付。

### 3.1 医生工作站前端交互界面（Web UI）
- [ ] 采用现代化前端框架（Vue / React 或极速原型 Streamlit）：
  - 问诊录入卡片（四诊收集：症状点选、舌象脉象选择）。
  - 推理结果仪表盘（诊断雷达图、主证、方剂卡片、药物剂量调整器）。
  - 嵌入式知识图谱可视化（直观展示从患者症状到最终处方的完整推理子图链条）。

### 3.2 知识图谱增强的大语言模型（GraphRAG 问答与解释）
- [ ] **消灭大模型胡说八道（零幻觉设计）**：
  - 传统 LLM 容易胡乱开药；结合 GraphRAG 后，由图谱提供 100% 确定性的方药和禁忌，由大模型负责自然语言对话、用药医嘱生成与古籍引经据典。
- [ ] **病案总结与古籍溯源**：
  - 调用 1,364 篇古籍经典库，自动为处方附上《伤寒论》《黄帝内经》原文依据。

### 3.3 系统备份、容器化与工程交付
- [ ] 编写一键部署 Docker-Compose 脚本（包含 Neo4j 数据库容器与 Python 后端服务）。
- [ ] 建立图数据版本快照备份机制。
